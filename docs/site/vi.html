CHÀO MỪNG ĐẾN FCC

Một cổng kết nối.
Nhiều cách xây dựng.

Free Claude Code định tuyến coding agent và API client tới các mô hình cloud hoặc cục bộ được hỗ trợ. Cấu hình trong Admin rồi sử dụng client yêu thích. Tính khả dụng, giá, điều khoản và khả năng của mô hình tùy thuộc nhà cung cấp.

01 / BẮT ĐẦU

Cài đặt và chạy.

Khởi động cục bộ, cấu hình một nhà cung cấp rồi kiểm tra kết nối.

Cài fork này từ mã nguồn. Lệnh dùng nhánh phát triển hiện tại của MoLik-Labs/FCC, không phải bản phát hành upstream. Python là runtime; bản Go vẫn đang thử nghiệm.
01

Lấy mã của fork

Cài Git và uv. Mở terminal hoặc Windows PowerShell, chạy: 

git clone --branch arena/5fe6a43f-fcc https://github.com/MoLik-Labs/FCC.git
cd FCC
uv sync --locked

Đây là nhánh đang phát triển; sau khi tích hợp vào main, chọn nhánh phù hợp. uv có thể cài Python 3.14.10. Bạn cần tự cài coding agent; cách này không tạo shortcut desktop hay tự cài công cụ tùy chọn.

02

Khởi động server

Trong thư mục FCC trên Windows, macOS hoặc Linux:

uv run fcc-server

Giữ terminal mở và dùng địa chỉ Admin trong log. Trong terminal thứ hai, vào lại thư mục này để chạy client.

03

Kết nối nhà cung cấp

Trong Providers, chọn nhà cung cấp, thêm key và lưu. Trong Model Config, chọn mô hình rồi bấm Apply. Ví dụ NVIDIA NIM dùng NVIDIA_NIM_API_KEY; lấy key tại NVIDIA. Giá, quyền truy cập và giới hạn do nhà cung cấp quyết định.

Nếu không liệt kê được mô hình, nhập chính xác provider-id/model-id. Với tài khoản subscription, dùng Providers → OAuth providers.

04

Chạy agent

Cài agent riêng, rồi chạy Claude Code hoặc Codex từ thư mục checkout; launcher có thể tự khởi động FCC: 

uv run fcc-claude
# hoặc
uv run fcc-codex

Chọn mô hình FCC trong client nếu có bộ chọn mô hình. Xem các launcher và tích hợp.

02 / KIỂM TRA

Gửi yêu cầu đầu tiên.

Sau khi server và nhà cung cấp sẵn sàng, liệt kê mô hình và gửi yêu cầu cục bộ.

Ví dụ dùng cổng mặc định; nếu log hiển thị địa chỉ khác, hãy dùng địa chỉ đó. Chọn ID mô hình có sẵn. Ví dụ NVIDIA yêu cầu nhà cung cấp tương ứng đã được cấu hình. 

curl "http://127.0.0.1:8082/v1/models?view=messages"
curl http://127.0.0.1:8082/v1/messages \
  -H "Content-Type: application/json" \
  -d '{
    "model": "nvidia_nim/nvidia/nemotron-3-ultra-550b-a55b",
    "max_tokens": 1024,
    "messages": [{"role": "user", "content": "Hello!"}]
  }'

Nếu bật Proxy Authentication, thêm header Authorization: Bearer <token>. Không để token trong log chia sẻ hoặc lịch sử shell. Thành công phụ thuộc nhà cung cấp, key và mô hình.

03 / CẤU HÌNH

Nhà cung cấp & mô hình.

Dùng dịch vụ cloud, endpoint tương thích riêng hoặc mô hình cục bộ.

01

Cloud

Thêm key hoặc kết nối OAuth trong Providers, rồi chọn mô hình. Có thể thêm và sắp xếp key theo số; key 1 là mặc định. Một số nhà cung cấp cần vùng, endpoint hoặc tài khoản bổ sung.

02

Custom provider

Chọn Providers → Custom providers → Add provider. Nhập base URL, định dạng API và key tùy chọn. Để trống Model IDs để tự khám phá, hoặc nhập ID chính xác rồi lưu.

03

Cục bộ

Khởi động model server trước. Dùng tiền tố lmstudio/, llamacpp/ hoặc ollama/ với ID chính xác. Refresh models hoặc bấm Test sau khi khởi động.

04

Định tuyến & fallback

MODEL là mặc định. Cấu hình tier, reasoning và thứ tự fallback trong Model Config. Một yêu cầu thất bại có thể tiêu thụ quota của nhiều nhà cung cấp.

Địa chỉ mặc định: LM Studio http://localhost:1234/v1, llama.cpp http://localhost:8080/v1, Ollama http://localhost:11434. Ưu tiên mô hình hỗ trợ tool và đủ context cho agent.

Editor và desktop

  1. Cài và chạy client trên cùng máy, cùng môi trường người dùng với FCC.
  2. Trong Admin → Integrations, bấm Connect ở thẻ tương ứng.
  3. Reload VS Code hoặc khởi động lại ứng dụng/IDE; chọn mô hình FCC nếu cần. Dùng Disconnect để ngắt kết nối.

Phải thoát hoàn toàn Claude Desktop trước khi kết nối hoặc ngắt kết nối. JetBrains ACP có bước thiết lập riêng; xem hướng dẫn từng tích hợp.

05 / THAM KHẢO

Gọi API trực tiếp.

Trỏ SDK hoặc HTTP client tương thích tới FCC.

GIAO THỨC ENDPOINT STREAMING
Anthropic Messages POST /v1/messages Thêm "stream": true
OpenAI Chat Completions POST /v1/chat/completions Thêm "stream": true
OpenAI Responses POST /v1/responses Luôn stream
Gemini POST /v1/models/{model}:generateContent Dùng :streamGenerateContent?alt=sse

Base URL mặc định của OpenAI SDK: http://127.0.0.1:8082/v1; Anthropic và Gemini: http://127.0.0.1:8082. Khi bật proxy authentication, dùng token làm API key hoặc bearer token. Khả năng của từng provider và mô hình vẫn được áp dụng.

06 / DI ĐỘNG

Điều khiển qua điện thoại.

Cấu hình Discord hoặc Telegram trong Admin → Messaging, rồi bấm Apply.

DISCORD

Kết nối bot

Tạo bot trong Discord Developer Portal, bật Message Content Intent; cấp quyền đọc, gửi, lịch sử và Manage Messages. Cấu hình token, channel ID được phép và thư mục tuyệt đối được phép.

TELEGRAM

Kết nối bot

Tạo bot với BotFather, lấy user ID dạng số; cấu hình token, user ID và thư mục tuyệt đối được phép. Với nhóm, cấp cho bot quyền xóa tin nhắn.

Khởi động lại nếu được yêu cầu. /stats xem trạng thái; /stop độc lập hủy công việc; /clear độc lập xóa hội thoại FCC trong chat. Trả lời một tin nhắn bằng lệnh sẽ nhắm tới yêu cầu hoặc chuỗi hội thoại đó. Voice notes hỗ trợ NVIDIA NIM hoặc Whisper cục bộ tùy chọn; xem thiết lập đầy đủ.

07 / QUAN TRỌNG

Vận hành an toàn.

Hiểu ranh giới tin cậy trước khi cho phép truy cập từ bên ngoài.

Admin và Code không có lớp xác thực Admin riêng. Client từ xa truy cập được các endpoint này có thể thay đổi cấu hình hoặc vận hành code session. Proxy Authentication bảo vệ proxy API; không mặc định coi nó bảo vệ Admin hay Code. Không mở cho mạng không tin cậy hoặc internet công cộng nếu thiếu kiểm soát truy cập độc lập.

Truy cập từ xa và tunnel

Cloudflare Tunnel, ngrok và Tailscale có thể cung cấp kết nối từ xa khi được cấu hình phù hợp. Giới hạn truy cập tại lớp mạng hoặc tunnel; chỉ có URL tunnel không đồng nghĩa với chính sách phân quyền. Kiểm tra cấu hình của nhà cung cấp và xác minh người không được phép không thể vào Admin hoặc Code trước khi sử dụng. HTTP từ xa không mã hóa token và nội dung ở lớp HTTP; dùng HTTPS hoặc tunnel riêng được bảo vệ phù hợp, kể cả với Claude Desktop.

Bảo vệ thông tin xác thực

  • Cấp quyền tối thiểu cho key, bot và tunnel; giới hạn user, channel và thư mục của messaging.
  • Không commit token hoặc đăng công khai; xóa thông tin nhạy cảm khỏi log và báo cáo lỗi.
  • Kiểm tra điều khoản, giá và thư mục mà agent có thể truy cập.
08 / BẢO TRÌ

Quản lý cài đặt.

Kiểm tra phiên bản, cập nhật có chủ đích và sao lưu trước khi gỡ.

VIỆC CẦN LÀM LỆNH / THAO TÁC
Xem phiên bản uv run fcc-server --version
Chẩn đoán uv run fcc-doctor
Cập nhật Dừng FCC, chạy git pull --ff-only và uv sync --locked trong checkout.
Gỡ cài đặt Dừng FCC và ứng dụng liên quan, sao lưu dữ liệu rồi xóa thư mục mã nguồn nếu không còn cần.

Checkout chứa .venv; dữ liệu FCC như ~/.fcc/ nằm riêng và không bị xóa cùng checkout. Không dùng fcc-update cho fork này: updater đi kèm gọi installer upstream. Script cài và gỡ upstream không quản lý checkout này.

09 / CHẨN ĐOÁN

Khi gặp sự cố.

Kiểm tra từng kết nối từ trong ra ngoài.

Không mở được Admin hoặc không kết nối được API

Kiểm tra server đang chạy, địa chỉ và cổng trong log, firewall và chính sách tunnel. Không mở Admin công khai chỉ để khắc phục lỗi.

Không thấy mô hình hoặc yêu cầu thất bại

Kiểm tra key, ID, quyền tài khoản và trạng thái provider. Với mô hình cục bộ, chạy model server rồi refresh hoặc bấm Test. Kiểm tra hỗ trợ tool và context.

Editor hoặc desktop client không thấy FCC

Chạy client và FCC trong cùng môi trường người dùng, kết nối lại trong Admin và khởi động lại client. Một số tích hợp cần thoát hoàn toàn hoặc thiết lập thêm.

Báo cáo lỗi như thế nào?

Chạy uv run fcc-doctor trong checkout; ghi lại phiên bản, mô hình đang dùng, mappings, các bước tái hiện và lỗi đầy đủ. Xóa key và dữ liệu riêng tư trước khi chia sẻ. Issues đang tắt trên fork này; chỉ dùng tracker upstream cho lỗi của upstream và bản phát hành của họ.

10 / PHÁT TRIỂN

Build và kiểm thử.

Python là runtime được hỗ trợ. Go vẫn là bản thử nghiệm chưa hoàn chỉnh, không phải server thay thế.

Cài uv rồi chạy checkout này với dependency đã khóa: 

git clone --branch arena/5fe6a43f-fcc https://github.com/MoLik-Labs/FCC.git
cd FCC
uv sync --locked
uv run fcc-server

Chạy ./scripts/ci.sh trên macOS/Linux hoặc .\scripts\ci.ps1 trên Windows. Đọc CONTRIBUTING.md trước khi tạo pull request. Nhánh phát triển vẫn còn lỗi type check toàn repository và một số generator benchmark cũ; xem checkpoint để biết trạng thái thực tế.

Với bản Go, đọc gocore/README.md và kế hoạch rewrite. Test fixture thành công chưa chứng minh parity toàn bộ service hoặc provider hiện tại.

11 / XUẤT BẢN

Về trang tài liệu này.

Trang tĩnh, không phụ thuộc runtime bên thứ ba, xuất bản qua GitHub Pages.

Build và xem thử từ thư mục gốc repository bằng Python 3:

python3 scripts/build_docs_site.py
python3 -m http.server 8000 --directory site-build

Mở http://localhost:8000 trên máy đang chạy server. Builder kiểm tra link cục bộ và chép trang cùng screenshot vào site-build/. Pull request được kiểm tra build; push lên main sẽ xuất bản qua GitHub Actions sau khi quản trị viên chọn Settings → Pages → Build and deployment → GitHub Actions. Workflow không xuất bản nhánh làm việc. Cần đưa thay đổi vào nhánh xuất bản và deploy thành công mới có URL công khai.
